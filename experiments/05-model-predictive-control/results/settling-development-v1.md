# MPC settling development results

Replacing one random torque sequence with a candidate generated by
proportional-derivative (PD) feedback raised the hold count from 0/12
to 12/12 on paired development cases. The result held for both analytical
RK4 and the published learned predictor under fixed work. The learned
planner's 3,600 decisions all exceeded 10 ms.

## Terminal speed cost

Terminal speed weights 0, 1, 4 and 16 all produced zero holds on the
six calibration cases. The predeclared tie break chose weight 1. On
the 12 confirmation cases, uniform RK4 held 0/12 with weight 0 and
0/12 with weight 1. PD held 12/12. The calibration's weight-zero
trajectories exactly matched the six historical uniform RK4
development trajectories after omitting timing and aligning the label.

## One feedback proposal

The optimizer used the original cost and drew the usual 16 candidates.
It reserved one of the 16 slots for a rollout that applied the existing
PD equation to each predicted state. The scoring loop selected the
lowest-cost feasible plan. Each MPC arm evaluated exactly 480
predictions per decision and 1,728,000 across its 12 episodes, with no
truth failures. Both guided variants held in all six nominal and all
six mild-friction cases.

| Controller | Holds | Median settling time (s) | Median position RMSE (rad) | Median torque effort (N²·m²·s) | Decisions over 10 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| Uniform RK4 MPC | 0/12 | — | 0.430 | 7.661 | 430/3,600 |
| Guided RK4 MPC | 12/12 | 1.810 | 0.387 | 1.044 | 16/3,600 |
| Guided learned MPC | 12/12 | 1.450 | 0.386 | 1.500 | 3,600/3,600 |
| Standalone PD | 12/12 | 1.975 | 0.412 | 0.484 | 0/3,600 |

The table uses the analytical probe's uniform RK4 and PD timing. The
learned probe repeated both reference arms. All 24 reference trajectories
matched after both timing fields were omitted. The uniform arm exceeded
10 ms on 15/3,600 decisions in that second run, showing timing variation
under ordinary host load. These are observed fixed-work decision times.

The guided RK4 actions matched standalone PD's torque evaluated on the
same observed state on 3,406 of its 3,600 decisions. The corresponding
count for the learned planner was 3,109. This shows how frequently the
guided planners applied the same torque as feedback, while the difference
in settling times reflects the decisions that differed. The fixed-work
learned probe had shorter median settling and used more torque effort
than the guided analytical arm. It used the existing checkpoint and
the scalar CPU inference interface.

## Reproduce the development runs

From separate clean checkouts of the source commits below, run the script
with a fresh output directory. Each output includes a manifest, raw
episode records, and paired results.

| Experiment | Source | Additional arguments |
| --- | --- | --- |
| Terminal speed cost | `51bf7e97f0b04a97bde9159024d3a70dc5e4c1fe` | |
| Guided analytical planner | `8ee0adae2f28e2b0f4eaa69c8d22ef61a3754f51` | `--feedback-proposal` |
| Guided learned planner | `af9dbfa4539df3d7623ff28b13855479d70ecd2a` | `--feedback-proposal --learned-checkpoint CHECKPOINT` |

```sh
uv run --locked python experiments/05-model-predictive-control/scripts/run_settling_development.py --output FRESH_DIRECTORY
```

For the learned run, use the original Experiment 04 canonical checkpoint
described in the [Phase 5 protocol lock](../configs/predictor-comparison-v1.md).
The learned probe uses the same development cases as the guided analytical
test. The mild-friction condition uses 0.08 N·m, with nominal predictor
context. These results describe the simulated one-link arm on the
development cases and support the next planner and inference experiments.
